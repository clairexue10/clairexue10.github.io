Custom Memory Allocator in C

CS 240 Foundations of Computer Systems · 2025

In Fall 2025, I took CS 240: Foundations of Computer Systems at Wellesley. The one-sentence summary I have for it is: it was truly a rewarding course.

Let me defend (expand) my statement a little. In this course (and the span of one semester), we went through - computational building blocks: digital logic, data as bits, integer representation, combinational logic, arithmetic logic, sequential logic, a simple processor - hardware-software interface: programming with memory, x86 control flow & procedures & call stack, representing data structures, buffer overflows - abstractions for practical systems: process model, shells, signals, threads, memory allocation, cache, virtual memory

In this project, I implemented a custom dynamic memory allocator in C to better understand how low-level memory management works beneath standard library functions like malloc and free. The allocator manages heap memory using an explicit doubly linked free list, allowing efficient traversal and constant-time insertion and removal of free blocks. Each heap block stores metadata in headers and footers, including size information and allocation status bits, enabling accurate block navigation, alignment guarantees, and safe backward traversal during coalescing. Payload addresses are carefully aligned to meet architecture requirements, and all pointer arithmetic is performed explicitly to maintain correctness at the word level.

The allocator supports first-fit allocation, block splitting, and immediate boundary-tag coalescing to reduce external fragmentation. When memory requests cannot be satisfied by existing free blocks, the heap is extended in page-sized increments using sbrk, and newly acquired space is merged with adjacent free regions when possible. Correctness is enforced through a heap consistency checker that validates block sizes, predecessor status bits, footer integrity, and heap boundaries. Together, these mechanisms highlight the systems-level tradeoffs involved in allocator design, illustrating how performance, safety, and memory layout constraints interact in real-world memory management.
